# Report rework — design

Status: implemented in 1.4.0. Supersedes `2026-03-29-live-report-server-design.md` and
`2026-03-29-html-triage-report-design.md`.

## Problem

The 1.2/1.3 report was one server-side template with a full page reload every ten seconds.

- It listed batches by number and never read `depends_on`, so it could not say what was ready,
  what was blocked, or what was waiting on the developer.
- The most useful data never reached it: client questions, paste-ready clarification text,
  "already fixed" notes, plan files, screenshots, risks, provider writes that failed.
- Four unlabelled colour chips per task (type, complexity, confidence, area), with colliding
  colours: `large` rendered as `medium`, confidence `medium` looked like complexity `medium`.
- Reloading wiped scroll position and every expanded row.
- A `done` batch rendered as "pending"; a half-written state file crashed the process; the skill
  launched a stale cached copy of the script; the server listened on every interface with no auth.
- Triage also had the model hand-write a second, static `triage-report.html` with a duplicated
  stylesheet: two renderers kept in sync by hand, and a large token cost on every triage.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Organising idea | Group by what happens next | The question a developer brings to the page is "what do I do now" |
| Layout | Work queue beside a detail pane | The queue answers "which"; the pane answers "what exactly" |
| Writes | Pipeline state is read-only; the report owns one file of inbox ticks | The report must never race an implement session |
| Static HTML report | Removed from triage | One renderer; `--snapshot` covers the archive use case |
| Build | None. Vanilla ES modules, zero runtime dependencies | The plugin ships by git clone; there is no install step |
| Model | Computed on the server | Testable without a DOM; one audited escaping path; reused by the snapshot |
| Fixtures | Generated by code, entirely synthetic | Git cannot hold empty lock directories or file ages, and the repository is public |
| Theme | Follows the system, both designed, manual override | |

## Architecture

```
scripts/report-server.mjs      CLI entry: args, one-shot modes, pid lifecycle
scripts/report/read.mjs        guarded file IO -> RawCycle
scripts/report/model.mjs       pure: (RawCycle, ticks, enrichment, now) -> view model
scripts/report/inbox.mjs       pure: inbox items and their tick state
scripts/report/ticks.mjs       report-inbox.<slug>.json (the only file the report writes)
scripts/report/markdown.mjs    escape-first renderer + plan section parser
scripts/report/estimates.mjs   free-text estimates -> minute ranges
scripts/report/enrich.mjs      gh + git lookups, cached, background
scripts/report/watch.mjs       change detection
scripts/report/server.mjs      HTTP routes, SSE, security headers
scripts/report/snapshot.mjs    single-file export
scripts/report/ui/             index.html, app.js, styles.css, theme.js, fonts/
```

**Reads are guarded.** triage and implement write JSON non-atomically. Each JSON read retries
twice (50 ms, 150 ms), falls back to the last good copy *of that file*, and reports a non-fatal
problem. The page shows a banner; nothing crashes.

**Change detection is a signature poll** (names, sizes and mtimes of the cycle directory,
`batches/`, `tasks/`, `attachments/`) every two seconds. `fs.watch` only shortens latency. On
Linux it fails silently on some mounts, and after `/taskflow:clean` moves the directory an
inotify watch keeps following the old inode; "fall back on error" never fires in those cases.
Claiming a batch is a `mkdir` of `<key>.lock`, which the poll sees as a new entry in `batches/`.

**Live updates are thin.** The SSE event carries only the model version; the client refetches
`/api/model` with `If-None-Match`. Polling takes over whenever the stream is down. A hidden tab
closes its stream (browsers allow six connections per origin). The model is also rebuilt every
30 seconds while anyone is watching, because lock ages cross thresholds with no file changing.
The version hash leaves out clock-driven fields so idle tabs do not re-render.

## Lanes

Guiding rule: **"Ready" equals, in the same order, what `/taskflow:implement` with no arguments
would auto-claim.** Since 1.5.0 that holds by construction: implement claims through
`scripts/taskflow.mjs claim`, which runs `gate.mjs` over this same model and takes the Ready lane.
The skill no longer restates the rules.

- A dependency is satisfied only when its *batch file* says `pr-created` or `done` — not merged.
- Claim order is numeric on `batch-(\d+)`; `batch-10` must not sort before `batch-2`.
- Self-dependencies are dropped and flagged. Every member of a dependency cycle is `dep-cycle`.
- State is never read from a plan file's header block; it goes stale after a re-batch.

First match wins:

| # | Status | Lock | Extra | Lane | Notes |
|---|---|---|---|---|---|
| 1 | `done` | any | | shipped | |
| 2 | `pr-created` | any | gh: merged | shipped | a leftover worktree raises an item with the `git worktree remove` command |
| 3 | `pr-created` | any | gh: closed unmerged | stale (`pr-closed`) | raises an item; dependants still treat the batch as complete |
| 4 | `pr-created` | any | open or unknown | pr-open | a lock here is normal and never flagged; failing checks or requested changes raise an item |
| 5 | `stale`, or every task in the batch file stale | any | | stale | still locked raises a stale-lock item |
| 6 | `in-progress` | yes | | in-flight | batch file untouched for 45 minutes: `quiet`, informational |
| 7 | `in-progress` | no | | in-flight (`orphaned`) | raises an item |
| 8 | `pending` or no batch file | yes | lock younger than 10 minutes | in-flight (`claiming`) | implement locks first and writes `in-progress` only after a round of provider calls |
| 9 | `pending` or no batch file | yes | lock 10 minutes or older | blocked (`stale-lock`) | raises an item with the `--unlock` command |
| 10 | `pending` | no | every task stale in the index | stale (`tasks-left-todo`) | |
| 11 | `pending` or no batch file | no | a dependency unsatisfied | blocked | `deps`, `dep-stale`, `dep-missing` or `dep-cycle`. Outranks row 12: answering alone would not free the batch |
| 12 | `pending` or no batch file | no | a blocking question is not answered or dropped (1.5.0) | blocked (`waiting-on-answers`) | questions on tasks that left "to do" do not count |
| 13 | `pending` or no batch file | no | otherwise | ready, `claimOrder = n` | `stackOn` names an unmerged dependency branch |
| 14 | unknown status string | any | | treated as pending | flagged, and a health problem |
| 15 | batch file unreadable | any | | last good copy, else as missing | flagged, and a health problem |

Until 1.5.0 a claimable batch with an open client question stayed in Ready with a marker. It now
leaves Ready when the question is *blocking*, because implement refuses it; a non-blocking open
question still only marks the row. See `2026-09-18-hosted-dashboard-design.md`.

## Inbox

Items have three origins:

- `index` — `tasks.<id>.needs[]`, `suggestions[]`, and `already_fixed` + `note` (schema v2).
- `plan-fallback` — a plan file's `## Open Question`, only when the task has no `needs` array at
  all. An explicit `[]` means triage looked and found nothing. The summary markdown is never
  parsed for items: its headings drift between cycles. It is shown whole as "Cycle notes".
- `derived` — computed from pipeline state: stale lock, orphaned claim, unresolvable dependency,
  pull request closed, pull request needing work, leftover worktree. Not tickable; they vanish
  when the state is fixed.

Identity is `kind:subject:key`. The text hash is stored on the tick as a **fingerprint**, not in
the id: when a re-triage rewords a ticked item it shows as "handled, text changed since", rather
than being silently unticked (constant churn under `--force`) or silently kept (stale). Orphaned
ticks are never pruned, so a transiently unreadable index cannot wipe them.

Resolutions are per kind and ordered, because a question takes two human steps:

| Kind | Resolutions | Parks in "waiting" |
|---|---|---|
| `question` | `sent`, `answered`, `dropped` | `sent`; also an unticked question with `delivered` other than `none` |
| `verify-close` | `verified`, `closed` | `verified` |
| `owed-write`, `todo` | `done` | |
| `suggestion` | `filed`, `dismissed` | |

`report-inbox.<slug>.json`:

```jsonc
{ "schema_version": 1, "slug": "<slug>", "cycle": "<last_triage>", "updated_at": "<iso>",
  "items": { "<itemId>": { "resolution": "sent", "at": "<iso>", "fingerprint": "<12 hex>", "title": "<snapshot>", "note": "" } } }
```

Writes are serialised and atomic (temp file + rename). A corrupt file is renamed
`.corrupt-<timestamp>` and replaced by an empty one. The file is not a dotfile, so
`/taskflow:clean` archives it with its cycle.

## Index schema v2

Written by triage; every new field is optional to the report. Full field notes live in
`skills/triage/SKILL.md` Step 7a.

- top level: `schema_version`, `dev_head`, `summary_file`, `suggestions[]`
- per task: `short_name`, `summary`, `priority`, `needs[]`, and the formalised `already_fixed` + `note`
- per batch: `rationale`

## HTTP surface

| Route | Purpose |
|---|---|
| `GET /` and a fixed static allowlist | the page |
| `GET /api/model[?cycle=]` | the view model, with an ETag |
| `GET /api/task/<id>` | rendered plan sections, files, attachment list |
| `GET /api/summary` | the triage summary, rendered |
| `GET /attachments/<id>/<file>` | screenshots |
| `GET /api/events` | SSE: `event: model`, heartbeat every 25 s |
| `POST /api/inbox` | tick or untick; 409 on a stale fingerprint; 403 on archives |
| `GET /api/cycles` | `live` plus each `archive/<name>/` that holds a state file |
| `GET /api/health` | name, version, script path — lets the skill detect an outdated server |
| `GET /api/status` | the pre-1.4 shape, kept |

The page shows client ticket text, so the server is closed by default:

- binds `127.0.0.1` only; Host header allowlist (DNS rebinding);
- CSP `default-src 'none'` with self-only script, style, font, image and connect; `nosniff`;
- the write route needs `application/json` and, when an Origin is sent, a same-origin one (CSRF);
- static files come from a map built at startup, never from a request path;
- a cycle id is matched against an enumeration of `archive/`, never joined into a path;
- attachments: name regex, type allowlist, realpath containment (symlinks cannot escape), and a
  `sandbox` CSP so an SVG from the provider cannot run script even when opened directly;
- markdown is escape-first with an http/https/mailto allowlist for links and bounded patterns;
  every URL taken from the index passes the same allowlist;
- `gh` and `git` run through `execFile` with no shell, and only URLs that match a GitHub pull
  request reach `gh`.

## Visual design

Made with the `frontend-design` skill: a written token plan, a critique of that plan against the
usual generated-page defaults, then the build, reviewed from screenshots in both themes at
1440, 1024, 800 and 400 px.

- **One idea:** every batch is a strip whose fields sit in fixed positions, under one sticky
  header row per lane. Position plus that header gives each value its meaning — the answer to the
  unlabelled chips. When the queue is too narrow for columns to line up, each value carries its
  own label instead.
- **Colour never carries text.** It is only a fill or an edge behind ink, and only for state that
  needs attention: marigold fill = needs you; blue fill = a session is working; carmine edge =
  broken; diagonal hatching = blocked (a texture, not a colour). Shipped work has no colour.
  Ordinal emphasis uses weight: `urgent` and `large` are bold; `low` confidence is the single
  marked value, because it halts implement.
- **Type:** Atkinson Hyperlegible Next and Mono for text and code — chosen for legibility under
  load and because they tell `1 l I` and `0 O` apart in provider ids. Big Shoulders Display, a
  condensed signage face, only for strip numbers, lane names and counts. Self-hosted woff2 with
  OFL licences; the page makes no external requests. Monospace is used for code only.
- **Dropped after the critique:** big-number stat cards (replaced by a compact lane row), green for
  shipped, coloured text pills, all-caps labels, middle-dot meta strings, arrows on links.
- **Motion:** one effect — a strip that changed in a live update shows a marigold outline once.
  Reduced motion is respected.
- **Words:** sentence case, plain verbs, an action keeps its name through the flow ("Mark sent"
  produces "Sent"). Empty lanes and errors say what to do next.

## Verification

- `node --test "test/*.test.mjs"` — lane table, dependency graph, numeric ordering, inbox origins
  and tick states, estimate parsing, markdown escaping and bounded run time, reader edge cases,
  HTTP security (Host, traversal, symlink escape, SVG sandbox, CSRF), SSE on `mkdir` of a lock,
  enrichment with an injected `exec`, snapshot escaping.
- `--print-model` against real cycles, never committed: Ready must list exactly what implement
  would claim; an archive with a hand-renamed index and locks left on finished batches must load
  with no false lock warnings.
- A browser pass over keyboard navigation, ticking, filters, the lightbox, a hostile SVG, archives
  and a live lane change.

## Known limits

- `batches/` is not scoped per developer. With several `state.*.json` files the server needs
  `--dev-slug`.
- Ticks are archived with their cycle; an item carried into the next cycle comes back unticked.
- Without `gh`, merged pull requests stay under "Pull request open".
- A snapshot links screenshots instead of embedding them, so it must sit in the cycle directory.
